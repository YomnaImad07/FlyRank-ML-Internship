Detecting content decline before it's obvious

A ranking-volatility approach to refresh prioritization, tested across ~70 pseudonymized clients.

Bayan Saleh  |  Search Intelligence — Refresh / Content Opportunity Scoring lane  |  Code & notebooks

Abstract

Content teams need to know which pages to review first, but simple rules based on traffic alone miss early warning signs. This project asks whether search-ranking instability predicts future decline better than raw impression trends alone. Using roughly 79 million rows of pseudonymized search performance data across about 70 clients, I engineered a position-volatility feature and trained a Random Forest classifier, validated with a client-grouped split to prevent leakage. The model reached 63.5% accuracy (macro F1: 0.617), with position volatility emerging as the single strongest predictor — ahead of query-mix and impression-based signals. The result is translated into a five-category reason-code system that content teams can use to prioritize review work with a stated reason, not just a score.

The problem

Teams managing large content libraries run into the same recurring decision: with thousands of pages and limited time, which ones should be reviewed or refreshed first? A common heuristic flags pages with decent content but low traffic — the logic being that the content is fine, it's simply not getting seen.

This project tests that heuristic against a trained model, and asks a second, harder question: does search-ranking volatility — how much a page's position swings day to day — carry a warning signal before a decline in traffic becomes obvious?

Data

Data comes from the FlyRank ML Internship warehouse release: roughly 17 months of daily search performance across about 70 pseudonymized clients, plus a 90-day query-level table, hosted as Parquet on Hugging Face.

  • fact_content_daily_performance — ~79M rows of daily impressions, clicks, and average position per content item.
  • fact_content_query_90d — query-mix signals per page over a trailing 90-day window.
  • dim_clients — per-client history depth, used to confirm the panel is unbalanced across clients before designing any time window.

Content items with fewer than 50 impressions in the prior 30-day window were excluded to avoid noisy, low-volume signals. No client names, domains, URLs, raw queries, or credentials appear anywhere in this write-up or the underlying code — all identifiers are pseudonymized hashes provided by the release itself.

Methodology

Every content item is scored on two signals: its 30-day impression change ratio, and its position volatility (the standard deviation of average search position over a 90-day window). The impression-change and query-mix features were built first, following the shape of the lane's starter notebook; position volatility is the feature I added myself, on the hypothesis that an unstable ranking is an earlier warning sign than a traffic drop that has already happened.

Label definition

A page is labeled declining if impressions dropped 20% or more month-over-month, using only data available before the outcome window — features come from the prior 30–60 day period, and the label from the following 30 days, so the model is never shown the outcome it's predicting.

Validation design

The first pass used a random train/test split, which lets pages from the same client appear in both sets — a form of leakage, since the model can partly memorize a client instead of learning something that generalizes. I replaced it with a GroupShuffleSplit on client ID, so no client appears in both training and test data. This is the honest evaluation: how the model performs on a client it has never seen.

Reason-code thresholds

Five categories were derived from the same two signals, using thresholds set by inspecting the data's distribution rather than an external ground truth:

  • Declining — impressions dropped 40%+ month-over-month
  • Recovering — impressions grew 40%+ and volatility is in the top quartile
  • Volatile — volatility is in the top quartile, with no clear directional trend
  • Stable–Growing — impressions grew 40%+ with low volatility
  • Stable–Flat — change within ±40%, with low volatility

Limitations & honest framing

This is a single-dataset, observational study. The reason-code thresholds were chosen by inspecting this data's distribution, not an external ground truth, and may not transfer to other verticals. The model identifies association, not causation — it shows that volatility co-occurs with decline in this data, not that fixing volatile pages prevents decline. Results should be read as decision-support signals, not guarantees, and the 63.5% accuracy figure describes this dataset's held-out clients, not a universal rate.

Ranked recommendations

  • 1Prioritize Declining pages first — the largest group, and the one with the clearest, most certain signal.
  • 2Route Volatile pages to manual review before any automated action — the model flags instability, not its cause.
  • 3Leave Stable–Growing pages alone. Protect, don't touch.
  • 4Hold Recovering pages for one more review cycle before deciding whether the recovery is real.
  • 5Stable–Flat pages are the lowest priority for limited review time.
